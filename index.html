Cryptographic Integrity Mathematical Model

In AES-GCM (Galois/Counter Mode), confidentiality is achieved by counter mode encryption, and integrity is computed over the Galois field $\text{GF}(2^{128})$:

Ciphertext: C = AES-CTR_K(IV, Plaintext)
Auth Tag: T = GHASH_H(AAD || C || Lengths) ⊕ AES_K(J_0)

Because the tag $T$ is mathematically tied to every bit of ciphertext and the secret key $K$, Eve cannot forge a valid tag for modified ciphertext without knowing $K$.

Conceptual Understanding: MITM Attacks & Defenses

Comprehensive educational overview aligned with college evaluation criteria.

Core Theory
Concept 1
Definition of MITM Attack

A Man-in-the-Middle (MITM) attack occurs when a malicious adversary secretly intercepts, reads, and potentially alters communication between two legitimate parties (Alice and Bob) who believe they are communicating directly.

  • Passive Eavesdropping: Adversary sniffs packets to violate confidentiality without modifying data.
  • Active MITM: Adversary intercepts, alters, or injects bogus packets, violating both integrity and authenticity.
  • Common Attack Vectors: ARP cache poisoning on local LANs, DNS cache spoofing, and Rogue Wi-Fi Hotspots ("Evil Twin").
Concept 2
Roles of Alice, Bob, and Eve

The classical cryptographic model divides participants into distinct functional roles:

  • Alice (Sender / Client): Initiates transmission with legitimate intent (e.g. online banking client, API caller).
  • Bob (Receiver / Server): The intended destination expecting unadulterated messages from Alice (e.g. bank server).
  • Eve (Adversary / Eavesdropper): Situated in the routing path; can intercept, inspect, alter, drop, or inject packets.
Concept 3
Message Interception

In unencrypted or compromised networks, packets travel over shared broadcast domains or untrusted routing nodes.

  • ARP Poisoning: Eve sends forged ARP replies to associate her MAC address with the gateway IP, redirecting Alice's traffic to Eve's interface.
  • Packet Capture: Tools like Wireshark/libpcap pull packets into Eve's memory buffer before they reach the default gateway.
Concept 4
Message Modification

Once intercepted, an active attacker alters payload fields before packet retransmission.

  • Financial Tampering: Replacing payee bank account numbers or altering payment amounts (e.g. from $10,000 to $95,000).
  • Command Injection: Changing administrative parameters or authorization flags from APPROVED to REJECTED.
  • Zero Verification: In plaintext HTTP, Bob has no mathematical mechanism to detect changes!
Concept 5
Message Forwarding & Camouflage

If Eve simply dropped intercepted packets, connection timeouts would immediately alert Alice and Bob of network malfunction.

  • Session Preservation: Eve recalculates TCP checksums and relays the modified packet to Bob.
  • Stealth: Alice believes Bob received her original request, and Bob believes the message originated authentically from Alice.
Concept 6
Encryption vs. Authentication

Crucial Distinction: Confidentiality (encryption) prevents eavesdropping, but does NOT prevent tampering without an authentication tag.

  • Malleability: Pure stream or counter ciphers allow bit-flipping attacks if integrity is unprotected.
  • AEAD (AES-GCM): Produces both ciphertext and a 128-bit GMAC authentication tag. If any bit changes, Bob's decryption strictly fails.
Concept 7
Prevention & Defense Mechanisms Against MITM
TLS 1.3 & PKI Certificates

X.509 digital certificates signed by trusted Certificate Authorities (CAs) authenticate server identities and negotiate session keys.

Mutual TLS (mTLS)

Both client and server present certificates to authenticate each other, preventing rogue proxy impersonation.

Dynamic ARP Inspection (DAI)

Enterprise network switches validate ARP packets against DHCP snooping databases to drop forged ARP replies on the wire.

DNSSEC & HSTS

DNSSEC prevents DNS cache poisoning; HTTP Strict Transport Security (HSTS) prevents SSL-stripping downgrades.
